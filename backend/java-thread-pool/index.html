Java 线程池：执行顺序、拒绝策略与容量估算

七个构造参数

参数 作用
corePoolSize 接收任务时优先创建工作线程的数量目标，可预启动核心线程
maximumPoolSize 当前允许的工作线程数上限
keepAliveTime、unit 超过核心数量的线程的空闲回收时间与单位，开启 allowCoreThreadTimeOut 后也适用核心线程
workQueue 等待执行的任务队列
threadFactory 统一创建、命名线程并配置守护属性、异常处理等
handler 任务无法接收时调用的 RejectedExecutionHandler

ArrayBlockingQueue 是固定容量的数组队列。LinkedBlockingQueue 可显式指定容量，默认上限是 Integer.MAX_VALUE，大流量会先累积排队时延和内存压力。SynchronousQueue 无缓冲，提交与接收需要直接交接。选队列时要一起考虑并发上限、瞬时积压和拒绝后的业务行为。

任务执行顺序

  1. 工作线程数小于 corePoolSize 时，优先尝试创建工作线程执行新任务。判断用的是工作线程总数。
  2. 达到核心线程数且池仍运行时，尝试把任务放入工作队列。入队后还会复查池状态，并在有任务但无工作线程时补充线程。
  3. 入队失败时，尝试创建非核心额度内的工作线程执行任务。
  4. 无法继续接收任务时触发拒绝策略。典型情形是队列满且达到线程上限，或线程池已关闭。

常见 OpenJDK 实现用一个 AtomicInteger ctl 同时保存运行状态和工作线程数，高 3 位为运行状态，低 29 位为线程数。RUNNING 接收新任务，SHUTDOWN 停止接收并继续处理队列，STOP 停止接收和处理队列并尝试中断工作线程，随后进入 TIDYING 和 TERMINATED。OpenJDK ThreadPoolExecutor 源码

拒绝任务会报什么错

滴滴一面原题。 默认 AbortPolicy 抛出 java.util.concurrent.RejectedExecutionException。其他三种策略按任务价值和调用线程的职责来选。

策略 行为
CallerRunsPolicy 池仍运行时，由提交者同步执行任务，减慢提交速度。调用者线程的响应时间也会增加
DiscardPolicy 静默丢弃当前任务
DiscardOldestPolicy 池仍运行时，移除队头等待任务，再尝试提交当前任务

也可以实现 rejectedExecution(Runnable task, ThreadPoolExecutor executor)，按任务语义计数告警、明确返回失败，或将可恢复任务落库或交给 MQ。已被丢弃且从未运行的 Future 可能一直等不到结果，选用静默策略时要处理这个调用方行为。

队列容量可先按 可持续处理速率（任务/秒）× 可接受排队时间（秒） 估量。若要覆盖短时突发，再用 (瞬时到达速率 − 可持续处理速率) × 突发持续秒数 估计积压，并检查延迟和内存是否允许。持续输入大于处理能力时，应靠限流、背压或拒绝策略约束积压。

线上调优看什么

在 Spring Boot 中把参数放到配置文件，通过 @Value 或配置属性加载。普通异步任务与定时任务使用独立池，后者可以采用 ScheduledExecutorService。给每个池配置有业务意义的线程名前缀，例如 schedule-pool-%d。可以在 afterExecute 捕获执行异常，使用 submit 时还要检查已经完成的 Future，因为任务异常通常被保存到结果里。

Dynamic-TP、Hippo4j 可用于运行时调参，能力取决于线程池和队列实现。用 Prometheus、Grafana 看活跃线程、队列堆积和等待时间、执行耗时、拒绝次数和 P99，再通过全链路压测找吞吐拐点。线上高 CPU 的定位步骤见 Linux 与服务排障。
