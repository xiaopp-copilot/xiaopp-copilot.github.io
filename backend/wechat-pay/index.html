微信支付：预支付、回调幂等和超时关单

一次微信支付是怎么完成的

浩鲸科技一面原题。 以 JSAPI 为例：

  1. 商户后端落本地订单，用商户订单号和金额等信息发起微信预支付请求，得到 prepay_id。
  2. 后端用 prepay_id 构造并签名客户端调起参数，前端拿到签名后的参数，调起微信收银台。
  3. 支付成功后，微信向商户通知接口异步回调。后端先验签，再解密通知内容并校验商户号、应用、商户订单号、金额和支付状态。也可调用查单接口主动确认微信侧结果。
  4. 用本地事务和条件更新推进订单状态、写支付账单。记录微信支付单号等可追溯标识，唯一约束和状态条件用于避免重复入账。成功的重复回调按幂等结果应答。

前端支付结果主要用于界面反馈，订单最终状态以验签通知或主动查单为依据。微信支付 JSAPI 开发指引

支付成功和延时关单同时到，听谁的

九方智投一面原题。 我从订单状态机、条件更新和本地事务讲起。落地时还要考虑支付平台通知与内部延时消息可以乱序抵达。

  • 收到支付成功。 先完成验签和比对。允许从待支付状态转换为已支付，在同一事务写支付记录和后续事件。更新 0 行时重新读状态，区分已成功处理、处在关单协调中，还是需要补偿的异常状态。
  • 收到延时关单。 只处理仍待支付的订单。先确认渠道状态，对未支付订单按渠道规则调用关闭。渠道已支付则走支付确认，关闭成功或查单确认已关闭后才把本地状态推进到已关闭。
  • 渠道请求超时或状态冲突。 保留可重试状态，重新查单，并按业务规则协调。若本地已经关闭却发现渠道已支付，要有对账和退款或人工补偿流程，避免静默漏记。

并发时用 WHERE status = 'PENDING' 等条件保护合法状态转换，用事务保证订单和账单原子更新。支付回调、主动查单、关单任务都可以重复进来，最终结果取决于渠道的确认状态和本地允许的状态迁移。微信支付 JSAPI 开发指引
