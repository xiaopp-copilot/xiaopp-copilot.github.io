Elasticsearch：查询 DSL、分片路由与 Lucene

常用 API 和字段映射

写入文档可用 PUT /index/_doc/id，由服务端生成 ID 时可用 POST /index/_doc。读取用 GET，删除文档或索引用 DELETE，通过 _search 查询，用 _bulk 批量写入、更新或删除，批量结果还要检查单条失败。

Mapping 中的 text 经过分词，适合全文搜索，keyword 常用于精确匹配、排序和聚合。其他类型有 integer、long、date、boolean、geo_point 等。analyzer 指定分析器，如内置 Standard 或额外安装的中文 IK 分析器。index 控制常规索引能力，部分字段类型也能通过 doc values 执行较慢的查询。

查询、过滤和聚合怎么写

用途 DSL
精确匹配 term 匹配一个已索引的词项，terms 匹配一组值，range 用 gt/gte/lt/lte 设定范围，exists 判断是否有索引值
全文检索 match 对输入分析后匹配，match_phrase 匹配带词序的短语，multi_match 搜索多个字段
布尔组合 must 必须满足并参与评分，filter 必须满足但不计分且可能被缓存，must_not 用于排除，should 通常用于可选匹配或加分
聚合 aggs 下的 terms 做分桶，avg/sum/max/min 做统计，cardinality 近似去重计数，date_histogram 按时间区间分桶

有 must 或 filter 时，should 默认可以一个都不匹配。业务需要至少命中一项时，显式设 minimum_should_match。sort 指定稳定排序，_source 选择返回内容，highlight 高亮匹配。浅分页用 from/size，默认结果窗口通常限制至 10,000，深分页可使用稳定排序的 search_after，并结合 PIT 保持一致视图。

主分片和副本怎么分布

滴滴一面原题。 一个索引可拆分为多个主分片。副本是主分片的拷贝，提供故障切换与额外读容量，主分片和相应副本应安排在不同节点。写入按 _routing 定位，默认使用文档的 _id。使用自定义 routing 时，后续按 ID 读、改、删需要带一致的路由键。

常规路由可以用 shard = hash(routing) % num_primary_shards 理解。沿用旧路由的索引会先对 num_routing_shards 取模，再除以 routing_factor 并取整，其中 routing_factor = num_routing_shards / num_primary_shards。实际公式看索引创建版本和是否使用分区路由。

主分片数无法在原索引上直接改成任意值。可以通过 reindex 迁移到新索引，满足条件时也能用 split 或 shrink 生成另一个索引。副本数可以按需要调整。Elasticsearch 路由字段

Lucene 段、refresh、flush 有什么关系

每个分片对应独立的 Lucene 索引。索引由不可变 Segment 组成，可包含倒排索引、用于排序和聚合的列式 doc values，以及取回字段所用的 stored fields。

  1. 写入操作更新内存缓冲并记录到 translog，用于恢复未包含在 Lucene 提交中的操作。
  2. Refresh 让新的段可搜索，形成近实时可见性。常见刷新间隔约一秒，取决于部署、索引活动及配置。可搜索和已持久化是分别由刷新、日志和提交决定的。
  3. Flush 做 Lucene commit 并切换 translog 代，提交过的旧日志可按机制清理。触发条件看版本和配置。
  4. Merge 在后台合并小段，重写存活文档。已经打删除标记的数据可在此时被物理清理，合并会消耗磁盘 I/O。
