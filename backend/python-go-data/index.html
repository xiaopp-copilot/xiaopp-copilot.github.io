Python、Go 与流批处理：后端补充面试题

Python 能处理哪些后端工作

博思软件面试原题。 面试问能否用 Python 编写简单脚本、处理数据。一个可讲清楚的例子是按行读取 JSON Lines 日志，校验和提取字段，按错误码聚合并输出统计。处理较大文件时可迭代读取，坏记录单独记录，结果保留输入数、成功数和失败数供核对。Java 和 Spring 常承担业务接口与微服务，Python 可承担数据处理、批处理脚本和服务集成。搜索 API 的 Python 示例见 Elasticsearch。

GIL 影响什么？ 在常见带 GIL 的 CPython 中，同一解释器内通常只有一个线程执行 Python 字节码。线程仍可重叠等待 I/O，CPU 密集型 Python 代码可以考虑多进程或支持释放 GIL 的原生库。具体还要看解释器构建模式。

多个慢接口怎么并行调用？ 支持异步的 HTTP 客户端配合 asyncio 可在等待网络时切换协程。需要控制并发上限，设置超时和取消处理。同步阻塞调用仍会卡住事件循环，要换异步库或显式交给线程执行。异步主要改善并发等待和资源占用，单次外部调用本身的时延仍由下游决定。

Go 的并发怎么理解

Go 是静态类型、编译型语言，部署时常见单个可执行文件。Goroutine 是 Go 运行时调度的轻量执行单元，Channel 用于不同 Goroutine 之间通信和同步。实际服务中还需用 context.Context 串联请求生命周期、超时和取消，避免后台任务常驻。Go 常见于 Docker、Kubernetes 等云原生系统。

Flink 和 Spark 各适合什么工作

Spark 常用于离线统计和周期报表。Flink 常用于低延迟的持续计算，例如实时游戏指标、营收看板。Spark 也有 Structured Streaming，常用微批方式，Flink 也能执行有界批作业。选型可以围绕时延、状态规模、事件时间、容错和已有数据架构展开。

Watermark 为什么能处理乱序事件？ 水位线表示系统对事件时间处理进度的估计。比如允许事先估出的乱序范围后，窗口可在水位线达到相应结束点时触发，晚到事件按窗口配置更新、侧输出或丢弃。多输入算子的水位线会受较慢或空闲分区影响，空闲分区需要合适的检测策略。

什么是状态后端？ Flink 中的有状态算子会保存计数、聚合和窗口中间结果等数据。状态后端管理运行时状态的存储与访问，检查点帮助故障后恢复一致状态。要说明端到端处理语义，还应把数据源可重放性、检查点与下游写入的事务或幂等能力放在一起看。Apache Flink 时间概念
