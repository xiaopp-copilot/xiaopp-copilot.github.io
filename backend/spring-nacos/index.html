Spring 与 Nacos：容器、代理、事务、事件和服务发现

Spring Boot 是什么，应用怎么启动

Spring Boot 把约定优于配置落到 Starter、自动配置和内嵌服务器上。Starter 汇总一组常用依赖，自动配置按类路径、配置和现有 Bean 等条件决定要注册什么。以 Servlet 应用为例，从启动类的 main 调用 SpringApplication.run 开始，准备环境和配置，创建并刷新应用上下文，处理组件扫描及自动配置，web 上下文在刷新过程中创建并启动嵌入式服务器。常见应用可打成可执行 JAR，启动时不需要额外部署到外部 Tomcat。

IOC、AOP 和 Spring 中的设计模式

IOC 将对象创建、装配和生命周期交给容器。依赖注入是实现方式之一，业务对象通过构造器、Setter 等接收所需依赖。AOP 把日志、权限、事务等横切逻辑织入目标方法调用。AspectJ 支持编译期或类加载期织入字节码，Spring AOP 通常在运行时创建代理。JDK 动态代理代理接口，CGLIB 生成子类，具体选择取决于框架和配置，可为有接口的类配置类代理。

这些设计模式可以对应到具体接口和行为。

模式 Spring 中的例子
工厂 BeanFactory 按定义创建和查找 Bean，调用方无须掌握实例化细节
单例 单例作用域通常在每个容器内为每个 Bean 定义保留一个实例，同一类可注册多个不同名称的定义
代理 Spring AOP 的方法增强，例如事务拦截
观察者 应用事件的发布和监听，监听器可订阅上下文生命周期或业务事件
构建者 SpringApplicationBuilder 逐步设置应用启动参数
策略 同一接口按业务或配置选择实现，例如不同的实例选择或处理策略

三级缓存如何解决循环依赖

以允许循环引用的单例 Setter 或字段注入为例。一级缓存 singletonObjects 存完成创建的单例，二级 earlySingletonObjects 存提前曝光的引用，三级 singletonFactories 存能提供早期引用的工厂。

  1. A 实例化后尚未填充属性，容器登记 A 的早期引用工厂。注入 B 时发现 B 尚未创建，于是实例化 B 并登记 B 的工厂。
  2. B 注入 A 时，从 A 的工厂取得早期引用，必要时由后置处理器提供早期代理。该引用进入二级缓存，三级工厂随即移除。
  3. B 完成初始化并进入一级缓存。A 注入 B 后完成初始化并进入一级缓存，容器清理 A 的早期缓存。

构造器互相依赖时，双方在实例化前就需要对方，无法先登记工厂。循环引用还受配置、Bean 作用域和代理条件影响。排查时先画出依赖图，判断能否把共同职责提到第三个组件。Spring Framework 依赖注入文档

Spring 能把 Bean 注入静态字段吗

深势科技一面。 @Autowired 的常规注入发生在容器管理的实例上，类级静态字段不能由它直接注入。新代码一般用构造器依赖和实例方法。历史代码如果必须保留静态入口，可以考虑三种间接处理。

  1. 在 @Component 上用非静态 Setter 接收依赖，再赋值给静态字段。例如 @Autowired void setTemplate(StringRedisTemplate template) { RedisUtil.template = template; }。
  2. 先注入普通成员变量。容器完成依赖注入后运行 @PostConstruct，在初始化方法中将它赋给静态引用，例如把实例上的 UserService 交给旧版静态工具方法。
  3. 让托管组件实现 ApplicationContextAware。在 setApplicationContext 保存上下文，静态工具类调用包装后的 context.getBean(UserService.class)。这会隐藏依赖，并增加多上下文和测试的隔离成本。

三种写法都要求调用发生在组件完成相应初始化后。

@Transactional 为什么失效，传播行为有哪些

同类方法用 this 发起内部调用，会绕开默认事务代理。private 方法无法由子类代理覆盖，也不能成为接口代理方法。异常被业务代码捕获后没有传播，同时事务也未标记回滚，拦截器可能按正常返回处理。默认回滚规则通常覆盖 RuntimeException 和 Error，受检异常可通过 rollbackFor 配置。

亿联网络一面问到了传播行为。 可以用外层订单操作调用内层记账操作来区分：

传播方式 已有事务时 无事务时
REQUIRED 加入现有事务 新开事务
REQUIRES_NEW 挂起外层，独立开启物理事务 新开事务
NESTED 在支持的资源上使用保存点 新开事务
SUPPORTS 加入现有事务 非事务执行
MANDATORY 加入现有事务 抛异常
NOT_SUPPORTED 挂起事务并以非事务方式执行 非事务执行
NEVER 抛异常 非事务执行

REQUIRED 共享物理事务，内层标记回滚后外层仍试图提交，可能收到 UnexpectedRollbackException。REQUIRES_NEW 的内层独立提交和回滚，通常要再借一个连接。NESTED 可以回滚到保存点，外层最终回滚时内层修改也会回滚。Spring 事务传播文档

@EventListener 怎么注册，事务回滚后怎样控制发消息

苏州科达面试原题。 在常见配置中，EventListenerMethodProcessor 实现 SmartInitializingSingleton，在常规单例初始化结束后的 afterSingletonsInstantiated() 查找监听方法。它通常经 EventListenerFactory 将方法包装成实现 ApplicationListener 的 ApplicationListenerMethodAdapter，注册到应用上下文。发布事件后，ApplicationEventMulticaster 找到适配器并调用 onApplicationEvent。适配器匹配事件类型、处理参数和 condition 的 SpEL 条件，再调用原方法。普通监听器默认可同步执行，异步行为要显式配置。Spring EventListener API

业务方法可发布应用事件，由 @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT) 在事务成功提交后调用 RabbitTemplate。事务回滚时，这个阶段的监听器不会执行。提交后到实际投递之间仍有故障窗口。需要可恢复投递时，把待发记录和业务更新一起提交，细节见 消息队列与 Outbox。

Nacos 怎么发现实例新增、变更和下线

挖角面试原题。 提供者按命名空间、分组、服务名与 IP、端口等信息注册实例。消费者拉取或订阅实例列表并维护本地缓存，再从健康实例中选择调用对象。

  • 旧 HTTP 客户端以定时心跳维持临时实例。笔记里的常见参数是每 5 秒上报、15 秒未更新标为不健康、30 秒后剔除，实际值与协议、版本和配置有关。持久实例通常由服务端主动探测，状态异常时可保留记录并标为不健康。
  • 早期 Naming 客户端可用 UDP 推送更新，兼有客户端拉取。Nacos 2.x Java SDK 的主要通信通道是 gRPC 长连接，临时实例和连接生命周期关联，重连后 SDK 恢复注册和订阅。gRPC 基于 HTTP/2，可在同一连接上承载多个流。
  • 配置中心要和服务发现分开讲。旧 HTTP 长轮询中，服务端可挂起订阅请求，例如约 30 秒，变更时返回通知，超时则结束请求，客户端再发出下一次轮询。客户端重新拉取配置、更新本地缓存或磁盘快照，再触发监听。@Value 或 Bean 是否刷新，还取决于 Spring Cloud Alibaba 的刷新配置和 Bean 的作用域。
