GUI Agent 每次操作后，如何确认界面状态真的变了

2026-07-05 Agent

假设让 Agent 在报表界面切到「上月」并读取摘要。我会先获取当前页面、可用筛选控件和原选中值，然后再操作。界面提供 DOM 或无障碍树时，优先根据角色和名称定位。截图可以帮助确认遮挡、弹窗和视觉状态。使用坐标时，应基于当前截图，并准备处理窗口大小和布局变化。

操作之后读什么

点击「上月」后重新观察界面，确认筛选值已改变、加载结束，而且报表标题或数据区与目标月份一致。导航、弹窗或列表刷新后，旧元素索引可能已经失效，应重新获取可用控件。界面文字是待处理数据。遇到不在任务内的弹窗或提交动作，运行时按既定权限处理。

把页面目标写成可以核对的状态

我会先为报表任务写一份简单的验收表。每个 UI 动作绑定它应观察到的变化。找不到预期状态时，先判断等待、重新定位还是结束。

阶段 观察信号 下一步
打开筛选区 报表标题与筛选控件可见 按控件角色和区域选择月份
切换到上月 筛选值显示「上月」 等待读取区域刷新
刷新完成 加载状态结束，报表标题对应目标月份 读取该区域摘要
服务返回错误 错误提示或权限提示可见 记录失败原因并结束或限次重试

初始快照只证明控件在某一时刻存在。若选项触发了整块组件重渲染，下一步从新快照里重新找同一区域。点击后焦点变化或按钮变灰都只算过程信号。验证应落到用户请求的可观测状态，例如目标月份和报表数据一起更新。

处理界面变动和等待

两个控件都叫「上月」时，可以先定位日期筛选所在区域，再按角色、标签和附近文本缩小范围。只能通过截图定位时，用当前截图的坐标系，并确认目标没有被悬浮层遮挡。页面在自动加载数据时，我会等待具体条件，例如进度提示消失和目标值出现都成立，避免用固定睡眠时间猜测刷新完成。

看不到结果时，记录最后一次有效页面标题、请求的筛选值、实际观察和失败阶段。这样下次重新执行可以从已确认状态开始。如果点击后产生了意料外的页面跳转，先重新确认当前页面上下文，避免沿用旧控件或继续执行剩余动作。

我的验证样本

准备一个加载慢的页面、两个名字相同但区域不同的按钮，再加一次窗口缩放。观察 Agent 能否用区域和角色消歧，能否等待新内容出现才读取，以及最终返回的摘要确实属于目标月份。调用返回成功只是一步证据，页面显示的目标状态才决定任务是否完成。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§9.8。
