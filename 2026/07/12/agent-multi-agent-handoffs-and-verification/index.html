多 Agent 协作从可验证的分工开始

2026-07-12 Agent

做一份发布检查报告，可以把文档核对与测试结果读取交给两个 Agent 并行处理。它们各自从不同材料获得证据，主 Agent 负责对齐版本并汇总。发布与否仍由有权限的人或确定的流程决定。这样的分工有明确输入和输出，也容易判断并行是否带来收益。

交接信息和共享状态

交接至少包含目标、输入版本、产出格式、证据位置和未解决项。各子任务只写自己的文件或目录，由主 Agent 合并。审核任务应能读取独立证据，例如执行结果或规则检查输出。遇到结论冲突，应回看材料版本和检测方法，再决定是否需要人工确认。

给子任务一个可合并的结果契约

以发布检查为例，两个子任务可以分别返回文档核对和测试核对结果。交接时明确它们必须检验同一个构建版本，并用结构化字段报告证据与缺项。

主 Agent 读取产物时要校验版本。文档结论来自 r42，测试结论若来自 r41，就先补查相同版本。子任务应能在消息丢失后通过任务 ID 找回上次结果，合并也应按任务 ID 和结果版本去重。需要写文件时，各自使用不同输出路径，主流程统一核对引用并整理交付文件。

判断并行是否真的缩短了任务

假设两项独立检查分别花 20 秒和 30 秒，串行读证据约需 50 秒。并行时理想等待是 30 秒，还要加上调度、结果转交和汇总的耗时。我会测从收到任务到交付的实际用时，把这些环节都纳入。若两项都依赖同一个限速服务，还应观察排队是否让并行失去收益。

我会让负责审核的 Agent 能读取实际日志或验收结果，并要求它定位具体失败项。文档和测试都确认通过时，汇总可以直接引用对应证据。某个检查失败或者只返回了部分结果时，主流程要按任务重要程度决定是否等待、补查或交付部分报告，并在那里明确剩余项。

先与单 Agent 基线对照

我会让单 Agent 和协作版跑同一组样本，记录验收通过率、实际用时和总成本，再模拟一个子任务失败及两个子任务的结果不一致。主流程应保留已验证部分，明确缺少的证据。只有分工引入了新证据、独立验证或明确的并行收益，协作成本才有对应的回报。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§10.2–10.5。
