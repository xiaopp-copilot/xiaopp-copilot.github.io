给 Agent 工具设计清晰的参数、错误和重试语义

2026-04-26 Agent

一个「为草稿添加标签」的工具，描述至少要说清对象类型、支持的标签和成功后返回什么。我会用 JSON Schema 限制参数形态，让执行端再检验草稿存在性、当前权限和业务状态。结构正确只能证明数据满足接口格式，真正是否能执行还要由业务系统决定。

工具应返回可处理的结果

成功时返回草稿 ID、写入后的标签和必要版本信息。参数错误返回错误字段及允许值，权限不足直接结束该路径，短暂服务繁忙才允许在预算内重试。网络超时有时意味着远端已经写入，所以修改接口宜支持幂等键，或提供按请求 ID 查询结果的能力。

工具边界可以沿读写划分。查询草稿与修改草稿使用独立权限，写入要求按动作确认。能用同一个查询工具表示的相似筛选就合在一起，避免工具列表堆出一批只差一个参数的方法。

我的联调样本

依次测试错误标签、无权限、正常写入和写入成功但客户端超时。最后一个场景要核对重复请求没有生成第二次写入，同时能查到第一次的结果。测试过这些路径，模型遇到错误时才有信息决定下一步。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§4.1–4.2、§4.5。
