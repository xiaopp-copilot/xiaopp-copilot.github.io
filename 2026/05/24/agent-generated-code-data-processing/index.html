让 Agent 用可复跑的脚本处理表格数据

2026-05-24 Agent

给出一组 CSV，让 Agent 按月份汇总订单金额。我的做法是让模型先确认列名、日期解析方式、币种和退款口径，再生成短脚本处理。脚本以源文件为只读输入，输出汇总表与异常行数量。金额计算使用明确的十进制精度，保留可核查的转换过程。

执行时有哪些约束

把程序放到隔离的工作目录，限制输入文件、输出目录和运行时间。常规统计无需开放外部网络。脚本读到无效日期和金额时，应记录行号并报告如何处理。输出至少保留每月记录数、纳入汇总的金额和被跳过的行数，方便复跑与对账。

一个可复跑的 Python 汇总示例

下面的脚本假定输入是同一币种，包含 date 和 amount 两列。脚本累计每月金额和有效行数，并报告格式异常的行号。输出按月份排序，便于用同一文件复跑并比较结果。

如果金额原样写成 1,200.00，要先约定分组符如何解析。混币种时应按币种单独聚合。重复行也要先确定是重复导入还是同一订单的多笔记录，不能仅凭某一列相同直接丢弃。

给产物留下一点运行信息

把脚本、输入文件指纹、纳入数量、异常行以及统计区间写到同一次任务的记录里。复核样本可以从 100 元订单、负 20 元退款和一行无效日期开始，预期该月计入两行、合计 80 元、异常一行。正式验收时再比对所有月份的合计及记录数。更换输入时沿用脚本和口径，修改口径时保存新的版本与小样本预期。

文件变大时，我会先看内存随什么增长。脚本逐行读入，汇总字典随分组数增长，异常行列表则可能随无效记录数增长。处理大文件时可以只保留内存中的异常计数，并把行号与原因写入单独的明细文件。若业务还需要按订单 ID 去重，就要另行维护唯一键，例如借助数据库约束。单月金额即使能对账，仍要核对去重前后的笔数和选中规则，才知道重复交易是否被按预期处理。

用第二份证据核对结果

我会用一个可手算的小表覆盖正常订单、负数退款、缺少日期和重复记录。再检查各月金额之和与有效行总金额一致，纳入与排除的记录数能对上原表。生成的脚本还可以保存下来，以同一口径处理下一批数据。对经常重复的任务，这比每次让模型在对话里临时计算更容易复核。
