MCP 工具越来越多时，怎样做按需发现

2026-05-03 Agent

多个 MCP 服务接入后，工具列表容易出现相近的名字。例如知识库、项目文档和工单都能搜索，模型得先知道该去哪一处查。我的做法是给应用一个轻量目录，包含服务来源、工具用途、适用对象以及读写类型，再按任务选出少量候选。

发现和执行各自做什么

发现阶段先根据任务和可访问资源过滤，再向模型提供候选工具的名称、用途和来源。确认使用某项能力后，才加载完整的参数 Schema 和必要示例。执行前仍要检查当前用户的资源权限，工具的 service + name 身份也应可追踪，防止名字相同的能力被混用。目录里的来源描述属于检索信息，授权由应用和服务端核验。

怎么知道工具选对了

用「查某项目手册」和「查某个工单的历史」做对照样本，再加一个同名项目、跨空间权限不同的场景。记录候选是否含正确工具、最终调用是否正确、为选择多花了多少时间。我的取舍是先用固定目录或简单筛选，当工具增长后再做更细的检索，并继续保留同一组回归样本。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§4.3、§4.8。
