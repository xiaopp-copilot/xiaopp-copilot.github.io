把耗时工具改造成可取消的异步任务

2026-05-10 Agent

一份大型报表要生成几十秒，用户中途可能问进度，也可能更改筛选条件。我会让工具启动任务后马上返回 job_id 和当前状态，后台工作进程继续生成。任务完成、失败或取消时再发事件，运行时据此恢复会话或更新界面。

把状态转换写进运行时

每个任务保存所属会话、输入版本、状态和结果引用。完成事件带任务 ID 与唯一事件 ID，消费者据此去重。收到取消请求时先记录取消意图，由工作进程确认能否终止。若用户已改了条件，旧任务晚到的结果仍可供查看，但要按版本隔离，避免覆盖当前输出。

事件也需要不同的处理方式。用户明确取消当前工作可以优先处理，普通进度可以合并，完全独立的只读任务可以并行。涉及外部写入的工作应留下可查询的状态，以便在重启时确认此前做到哪一步。

我会模拟的三种时序

重复投递同一个完成事件、取消时结果恰好返回、任务执行中服务重启。三种情况都应能得到明确终态。验收既要看 Agent 的回复，也要查任务表和最终产物，确认没有发生重复展示或错误覆盖。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§4.7。
