用 Trace 定位 Agent 失败发生在哪一步

2026-06-14 Agent

知识库助手回答错了，可能是资料没被索引、检索漏了依据、模型忽略了证据，或者结果校验没执行。我会用一个 Trace ID 串起任务，并把每次模型请求、检索、工具调用与结果校验记成有父子关系的 span。

运行记录里保留什么

模型 span 记录版本、时间和用量，检索 span 记录查询意图和候选资料 ID，工具 span 记录类型、参数校验结果、耗时和错误类别。最终 span 记录任务是否满足验收条件。含隐私的正文和参数可以保留脱敏摘要或受控引用，让调试能定位到具体路径，也便于限制原文的访问和保留期限。

从一条失败记录提出下一步

例如用户问新版接口的限制，回答引用了旧版。先查新版是否出现在检索候选，再查候选是否进入模型输入。新版从未进入候选，就先测版本过滤与召回。新版有依据但回答引用了旧版，就检查资料排序和生成约束。我会为定位到的原因保存一个回归用例，改动一项后重放同类样本，看看失败是减少了，还是转移到了下一步。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§6.8–6.10。
