用 JSON 路径识别嵌套字段的迁移与删除

2026-06-04 实习

更新扩展字段树后，有些还被制度引用的管控要素失去了显示名称。最初的字段差集思路在基本信息和报销单的扩展字段树上遇到了一个边界。子字段换了父节点，旧 JSON 路径也会消失，直接按旧路径判定删除会产生误差。

两处需要区分的标识

我梳理了 Java 服务里的路径比较。一级路径在新模型中找不到时，可列为删除候选。对于更深的路径，还要检查它是否随父节点迁移，或是否已经以新完整路径保留。两个检查都没有命中，才进入删除与引用判断。

费用行为的校验还遇到一个关系查询问题。稽核单元里的事项 ID 在该场景下指向「经济事项与费用行为的关系记录」。只去费用行为表按主键查询会查不到，因为参与稽核的是两者的关联。

我的思考

路径表达字段在树中的位置，关系记录表达一项业务组合。两者都适合用于定位，但在判断对象是否消失前，得先核对它们各自的含义。设计测试时，我会分开覆盖字段换父节点、实际删除，以及同一费用行为关联多个事项的情况。
