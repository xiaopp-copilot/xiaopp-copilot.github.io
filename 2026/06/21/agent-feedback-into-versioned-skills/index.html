把失败轨迹整理成可以验证和回滚的 Skill 改动

2026-06-21 Agent

如果表格整理 Agent 反复漏掉单位，我会先挑几条失败轨迹和一条成功轨迹，找共同的前置条件。问题可能出在列名解析，也可能出在输出时漏了单位。能归纳出的经验应写成一条具体规则，例如「汇总前检查每列的单位，单位混用时先标出异常行」。

经验落到合适的位置

稳定事实存知识库，带判断条件的步骤写进 Skill，重复且可确定验证的计算做成工具。让我更愿意复用一项经验的，是它有适用范围、来源和验收条件。过去的轨迹里可能有偶然成功的操作，也可能含敏感数据。只提炼能解释、可重测的部分，保留原样本的受控引用。

从三个样本推导一条能测试的规则

假设第一条失败样本的列标题是「销售额（万元）」，第二条把单位放在说明页，第三条正常样本的每个金额都明确标为元。先标注每次错误从哪里开始。列名本身带单位却在结果中丢失，可以改输出校验。单位在说明页且未读取，则需要补取证步骤。这两类样本可以分开验证。

我会把候选规则写成两句。若数值列或说明页有单位，记下单位来源。若同一列单位混用，先标记冲突并停止该列求和。相应的验收要能检查到单位字段、证据位置和冲突说明。对于明确的单单位输入，输出结果应与旧版一致。这样团队能复核规则覆盖了哪些数据，也能发现某次更新是否让原来简单的任务多花了一轮。

一次修订保留哪些证据

内容 示例
触发条件 表头或说明页提供单位
失败表现 汇总金额丢了「万元」标记
改动 计算前记录单位和来源，混用时先报告冲突
回归用例 表头单位、附页单位、混用单位、单一单位
变更版本 记录通过的用例和可回滚的旧版本

正式更新前先把新旧 Skill 分别跑同一小批材料。对于尚未稳定的问题，可保留为待验证经验，等有可复现样本再升级为普遍规则。遇到一次偶发失败时，我更愿意先改善可观测性，等清楚它是模型行为、工具返回还是输入变了，再决定改哪层。

改动如何生效

让 Agent 提出小范围差异，由维护者审核并跑回归。样本同时覆盖触发条件和无需应用新规则的正常输入。验证后给 Skill 标版本，记录变更原因和回滚目标。如果规则扩大了适用范围或改变工具权限，需要由运行时的权限配置单独评估。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§8.4–8.5。
