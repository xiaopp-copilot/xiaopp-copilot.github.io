搭语音 Agent 时，先量延迟和打断恢复

2026-06-28 Agent

做语音问答原型时，可以先用语音活动检测、语音识别、语言模型和语音合成组成级联链路。我会记录用户停止说话、识别结果可用、模型开始输出、音频开始播放这几个时点。这样能看到延迟来自等停顿、等模型，还是音频合成和播放队列。

流式处理与打断

识别可以逐步返回文本，稳定片段进入下一阶段，模型生成的完整短句可交给 TTS。用户在播放时开口，新轮次应能让旧轮次停止生成，清掉仍在排队的旧音频，并在会话状态里保留用户实际听到的部分。后端工具若已经启动，则根据工具是否可取消来处理，并按轮次隔离晚到的结果。

我会如何验证

用短问句、自然停顿、长问题和播到一半打断几种场景，记录从用户停说到第一段可听音频的时间，也记录开始打断到旧音频停下的时间。听一遍录制结果，核对系统有没有把思考时的停顿误当句末。只有这组基线测清楚，才好判断是否需要更紧耦合的音频架构。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§9.2–9.6。
