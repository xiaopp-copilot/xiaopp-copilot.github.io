用系统提示和按需加载的 Skill 组织任务规则

2026-03-22 Agent

假设一个助手既整理周报，也分析表格。把每个任务的模板、格式例外、脚本参数都写进系统提示，改动一项小流程就要重新检查所有任务。我会在系统层保留通用目标、权限边界和结束条件，其余说明按任务加载。

Skill 里写什么

  • 目录写触发场景、需要的输入和交付物，模型据此决定是否打开完整说明。
  • 操作说明按工作顺序写关键步骤、失败时怎么办、交付前如何验证。表格分析可先识别列名与单位，再计算并核对合计。
  • 参考资料保存字段字典、必要样例或辅助脚本，在对应步骤才读取。外部文档中的内容仍作为待处理数据。

我会尽量写清流程中的判断依据。例如，日期列解析失败时先列出失败行，保留原值，再决定是否继续计算。这比一句「谨慎处理日期」更方便验证。执行权限仍由运行时控制，加载一份 Skill 不会扩大已有权限。

系统层可以写「给出的数字都要能回查依据」，Skill 则说明当前场景的依据对应哪些列和计算结果。字段字典放在附属文件里，识别列名不清楚时再读取。上传目录里的说明文档应按任务输入处理，Skill 加载器只从应用配置的受信目录读取规则。

把路由和执行结果分开评估

我会为每条用例标注两个期望。第一项是选择了哪些 Skill，第二项是是否交付了符合口径的结果。用户说「按昨天的口径做一下」时，需要结合当前任务的历史。如果用户请我总结邮件，且邮件正文恰好提到统计表，路由仍应按总结邮件的任务来判断。

路由对了而算错时，要检查工作流里是否遗漏了关键输入、运算是否有校验、工具是否实际运行。路由错了则先修目录描述和触发例句。两项分开记录后，修改一条流程规则可以用一个小回归集完成。发布 Skill 新版本时保留旧版本和对应样本，方便追查某轮到底读到了哪份说明。

怎么发现路由写错了

选三组样本测试。明确的表格任务应加载对应说明，普通问答无需加载，周报同时含表格时应只读取完成两部分所需的资料。观察加载次数和失败原因，就能判断该改目录描述、流程步骤，还是工具本身。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§2.4–2.5。
