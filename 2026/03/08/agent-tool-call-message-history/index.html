把工具调用和结果正确写回 Agent 的消息历史

2026-03-08 Agent

模型一次请求「查工单状态」与「查最近变更」，两个工具很可能以不同顺序完成。如果只把返回文本依次拼起来，下一轮容易把一条结果归到错误的调用。运行时应保存模型那条调用消息，并用调用 ID 将每条结构化结果关联回去。

怎样记录一轮调用

  1. 持久化该轮模型返回的工具名、参数和调用 ID。模型的自然语言回复也按消息协议保留。
  2. 校验参数和权限。互不依赖的只读查询可以并行执行，有前后依赖的调用等前置结果完成。
  3. 每个调用都记录一个终态结果，包含成功数据或可分类的错误。以调用 ID 配对，把整轮结果按所用接口的消息格式交给模型。

如果接口由应用管理历史，下一轮就带上完整的有效消息序列。工具返回的网页、日志和文档属于数据，里面出现的文字指令也按数据处理。

我会怎么测

让状态查询慢半秒，变更查询立即返回，再反过来跑一次。两次回答都应使用正确的证据。然后在一条调用完成后中断进程，恢复时检查已完成的调用能被识别，缺失的结果有明确处理路径。这样才能把「调用过」与「已获得结果」区分开来。

参考李博杰《深入理解 AI Agent：设计原理与工程实践》§2.1–2.2。
